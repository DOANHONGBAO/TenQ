# API Contract (v1)

- Status: Proposed in Phase 01. The OpenAPI schema generated by FastAPI in later phases must match this document; differences are bugs in one of them.
- Base path: `/api/v1`. Public URL: `https://<vercel-domain>/api/v1/...` (proxied to the origin, see architecture section 2).

## 1. Conventions

- JSON only (`Content-Type: application/json; charset=utf-8`). Unknown request fields are rejected (`422`).
- Timestamps: ISO 8601 UTC with `Z`, millisecond precision (`2026-10-17T08:15:30.123Z`). Dates: `YYYY-MM-DD` (UTC game date).
- Every response carries `X-Request-ID` (echoed if the client sent a valid one, otherwise generated).
- All responses: `Cache-Control: no-store`, except `GET /puzzles/{date}/answer` for past dates (`public, max-age=86400`).
- Authentication: the `tenq_sid` cookie (signed, HttpOnly). Endpoints marked *session* return `401 SESSION_REQUIRED` without it.

## 2. Error model

Every non-2xx response uses one envelope:

```json
{
  "error": {
    "code": "ATTEMPT_LIMIT_REACHED",
    "message": "You have used all 10 questions for today.",
    "request_id": "01JABCDEF...",
    "details": {}
  }
}
```

`code` is stable and machine-readable; `message` is for humans and may change. `details` is optional and never contains secrets.

| HTTP | `code` | When | Question charged? |
|------|--------|------|-------------------|
| 400 | `BAD_REQUEST` | Malformed JSON, missing or malformed `Idempotency-Key` | No |
| 401 | `SESSION_REQUIRED` | Missing, invalid, or expired session cookie | No |
| 403 | `TURNSTILE_FAILED` | Turnstile token rejected | N/A |
| 403 | `ANSWER_NOT_AVAILABLE` | Answer requested for today or a future date | N/A |
| 403 | `FORBIDDEN_ORIGIN` | (Nginx) request did not come through Vercel | N/A |
| 404 | `NOT_FOUND` | Unknown route or date without a puzzle | N/A |
| 409 | `QUESTION_IN_PROGRESS` | Another question from this player is being judged | No |
| 409 | `ATTEMPT_LIMIT_REACHED` | 10 questions already used | No |
| 409 | `GAME_FINISHED` | Game already won | No |
| 409 | `DUPLICATE_QUESTION` | Same normalized question already asked today (OQ-05) | No |
| 422 | `VALIDATION_ERROR` | Schema violation (types, unknown fields) | No |
| 422 | `INVALID_QUESTION` | Fails deterministic question checks (OQ-04) | No |
| 422 | `IDEMPOTENCY_KEY_REUSED` | Same key sent with a different body | No |
| 429 | `RATE_LIMITED` | Rate limit hit; `Retry-After` header set | No |
| 500 | `INTERNAL_ERROR` | Unexpected server error | No |
| 502 | `AI_INVALID_RESPONSE` | Model output could not be validated | No |
| 503 | `AI_UNAVAILABLE` | Provider error, timeout, quota, or budget exhausted; `Retry-After` set | No |
| 503 | `SERVICE_UNAVAILABLE` | Redis or SQLite unavailable; Turnstile verification unavailable | No |

## 3. Shared schemas

```ts
type Answer = "YES" | "NO" | "IRRELEVANT" | "PENALTY" | "WIN";
type GameStatus = "not_started" | "in_progress" | "won" | "lost";

interface HistoryEntry {
  number: number;            // 1..10
  question: string;          // as submitted (trimmed)
  answer: Answer;
  asked_at: string;          // timestamp
}

interface GameState {
  game_date: string;         // YYYY-MM-DD
  status: GameStatus;
  max_questions: 10;
  used: number;              // 0..10
  remaining: number;         // 10 - used
  in_progress: boolean;      // a question is being judged
  history: HistoryEntry[];
  started_at: string | null;
  finished_at: string | null;
  duration_ms: number | null;     // finished_at - started_at
  server_time: string;
  next_reset_at: string;          // next 00:00 UTC
}
```

## 4. Endpoints

### 4.1 `GET /health` and `GET /ready`

No session. `200 {"status":"ok"}`. `/ready` returns `503 SERVICE_UNAVAILABLE` if Redis or SQLite is unreachable. Not rate limited by the application.

### 4.2 `POST /session`

Creates an anonymous session after Turnstile verification.

Request:
```json
{ "turnstile_token": "0.AbC..." }
```
Responses:
- `201 Created`: `Set-Cookie: tenq_sid=...; HttpOnly; Secure; SameSite=Lax; Path=/api; Max-Age=31536000`, body `{"display_name": "Player-7F3A"}`.
- `200 OK`: a valid session cookie was already present; nothing changes.
- Errors: `403 TURNSTILE_FAILED`, `429 RATE_LIMITED`, `503 SERVICE_UNAVAILABLE`.

### 4.3 `GET /game/today` *(session)*

Returns the caller's `GameState` for the current UTC day. If the player has not asked anything today: `status = "not_started"`, `used = 0`, empty history.

Until Phase 06 adds `POST /session` with Turnstile, this endpoint also starts the anonymous session: without a valid `tenq_sid` cookie it sets a new one (`HttpOnly; SameSite=Lax; Path=/api; Max-Age=31536000`, plus `Secure` in production).

`started_at` is when the first charged question was received (its reservation time); `finished_at` is when the winning or tenth question was committed. Both come from the server clock only.

### 4.4 `POST /game/today/questions` *(session)*

Headers: `Idempotency-Key: <UUID v4>` (required). The client generates one key per user submission and reuses it for retries of that submission only.

Request:
```json
{ "question": "Is it an animal?" }
```

Deterministic checks for English yes/no questions (BR-05) before any AI call (OQ-04), failing with `422 INVALID_QUESTION` and `details.reason`:

| `reason` | Rule |
|----------|------|
| `too_short` / `too_long` | Trimmed length below 3 or above 150 characters |
| `invalid_characters` | Characters outside printable ASCII after normalization |
| `not_a_question` | Does not end with `?` |

Response `200 OK`:
```json
{
  "number": 4,
  "answer": "NO",
  "game": { "...": "GameState after this question" }
}
```

Replays of a completed submission return the same `number` and `answer` with header `Idempotent-Replayed: true`; `game` is the player's current state. The request body accepts only `question`; any other field (for example `remaining`, `used`, `status`) is rejected with `422 VALIDATION_ERROR`.

Errors: `400`, `401`, `409 QUESTION_IN_PROGRESS | ATTEMPT_LIMIT_REACHED | GAME_FINISHED | DUPLICATE_QUESTION`, `422 INVALID_QUESTION | IDEMPOTENCY_KEY_REUSED | VALIDATION_ERROR`, `429`, `502 AI_INVALID_RESPONSE`, `503 AI_UNAVAILABLE | SERVICE_UNAVAILABLE`.

### 4.5 `GET /leaderboard/today?limit=50` *(session optional)*

`limit` 1..100, default 50.

```json
{
  "game_date": "2026-10-17",
  "entries": [
    { "rank": 1, "display_name": "Player-7F3A", "questions": 4, "duration_ms": 182340 }
  ],
  "me": { "rank": 17, "questions": 7, "duration_ms": 610200 },
  "total_winners": 128
}
```

Only won games are listed (OQ-07). `me` is `null` without a session or if the caller has not won today. Ranking: `questions` ascending, then `duration_ms` ascending (server-measured, millisecond resolution), then earlier `finished_at`, then player hash; the order is total and deterministic. Entries carry only the anonymous `display_name` (`Player-` + first 6 hex characters of the keyed player hash).

### 4.6 `GET /leaderboard/{date}?limit=50`

Same shape for a past date (`date < today`), served from SQLite. `404 NOT_FOUND` if no puzzle existed.

### 4.6a `GET /puzzles/today`

No session. Public facts about today's puzzle; the word is never included. Calling it pins today's word server-side if this is the first request of the UTC day.

```json
{ "game_date": "2026-10-17", "server_time": "2026-10-17T12:00:00.000Z", "next_reset_at": "2026-10-18T00:00:00.000Z" }
```

`Cache-Control: no-store`. Errors: `503 SERVICE_UNAVAILABLE` if the vocabulary is not seeded.

### 4.7 `GET /puzzles/{date}/answer`

No session. Only for `date < today` (UTC), per BR-12 and OQ-08.

```json
{ "game_date": "2026-10-16", "word": "lighthouse" }
```

Errors: `403 ANSWER_NOT_AVAILABLE` for today or future dates, `404 NOT_FOUND` for dates without a puzzle.

## 5. Versioning

Breaking changes go to `/api/v2`. Adding optional response fields is not breaking; the frontend must ignore unknown fields.
